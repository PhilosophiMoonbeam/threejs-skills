# Migrating to Three.js 0.185.1

## Scope and upgrade rule

- Target **exactly `three@0.185.1`**. Do not copy APIs from `dev`, revision 186, or later documentation into a 0.185.1 project.
- This checklist starts at the oldest evidenced package baseline, r118, and covers only rendering, lifecycle, loaders, geometry, controls, materials, shaders, and post-processing.
- Upgrade very old applications in increments of about ten revisions and clear every deprecation before the next increment. The [official migration guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide) recommends this because warnings normally survive only ten releases.
- Keep core, addons, examples, decoder assets, and type declarations on one revision. The [`three@0.185.1` package exports](https://github.com/mrdoob/three.js/blob/r185/package.json) define `three`, `three/addons/*`, `three/webgpu`, and `three/tsl`.
- Treat `[WebGL]` and `[WebGPU]` items as backend-specific. Do not assume renderer classes, render targets, shader systems, or post-processing pipelines are interchangeable.

## Renderer and lifecycle

- **r147:** old point/spot-light scenes may change because `decay` now defaults to `2`. Keep inverse-square decay and retune intensities rather than restoring `1` for new PBR work. [146 → 147](https://github.com/mrdoob/three.js/wiki/Migration-Guide#146--147)
- **r155 [WebGL]:** remove `renderer.useLegacyLights`; physically based lighting is the default. Re-baseline legacy light intensities and exposure. [154 → 155](https://github.com/mrdoob/three.js/wiki/Migration-Guide#154--155)
- **r158:** normalize application-supplied quaternions before assigning them. [157 → 158](https://github.com/mrdoob/three.js/wiki/Migration-Guide#157--158)
- **r163 [WebGL]:** WebGL 1 is unsupported. Require WebGL 2; request `stencil: true` explicitly when stencil operations are used. [162 → 163](https://github.com/mrdoob/three.js/wiki/Migration-Guide#162--r163)
- **r174:** `Timer` no longer observes page visibility automatically. Call `timer.connect(document)` only when hidden-tab time must be excluded. [173 → 174](https://github.com/mrdoob/three.js/wiki/Migration-Guide#173--174)
- **r179:** import no timer addon; `Timer` is in core. [178 → 179](https://github.com/mrdoob/three.js/wiki/Migration-Guide#178--179)
- **r181 [WebGPU]:** replace deprecated `renderAsync()`, `clearAsync()`, and feature-detection async variants with synchronous calls after `await renderer.init()`. `setAnimationLoop()` initializes the renderer automatically. [180 → 181](https://github.com/mrdoob/three.js/wiki/Migration-Guide#180--181)
- **r182 [WebGL]:** replace `PCFSoftShadowMap` with `PCFShadowMap`; PCF is now the soft/default mode. [181 → 182](https://github.com/mrdoob/three.js/wiki/Migration-Guide#181--182)
- **r183:** replace deprecated `Clock` with core `Timer`; call `update()` once per frame, then read `getDelta()` and `getElapsed()`. [182 → 183](https://github.com/mrdoob/three.js/wiki/Migration-Guide#182--183)
- **r183 [WebGPU]:** replace `WebGLCubeRenderTarget` with `CubeRenderTarget`; reconsider old WebGPU shadow bias values after the shadow changes. [182 → 183](https://github.com/mrdoob/three.js/wiki/Migration-Guide#182--183)
- **r185 [WebGPU]:** premultiplied-alpha compositing changed. Prefer an opaque scene background or clear color unless HTML-background compositing is required. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)
- **r185:** when `matrixAutoUpdate` is false and code writes `object.matrix` directly, also set `object.matrixWorldNeedsUpdate = true`; `updateWorldMatrix()` now honors the flag. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)
- On teardown, stop the animation loop and remove observers/listeners before disposing owned controls, timers, loaders with workers, render targets, textures, geometries, materials, skeletons, and the renderer. Removing an object does not release GPU resources. [Official disposal guide](https://threejs.org/manual/en/how-to-dispose-of-objects.html)

## Imports and loaders

- **r161:** replace removed `build/three.js` and `build/three.min.js` scripts with ES modules. [r160 → r161](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r160--r161)
- Use `three/addons/...`, not `three/examples/jsm/...`, for documented addon imports. Both resolve in 0.185.1, but the addon alias is canonical. [`three@0.185.1` package exports](https://github.com/mrdoob/three.js/blob/r185/package.json)
- **r176:** do not depend on `GLTFLoader` performing WebP/AVIF support detection; that detection was removed. [175 → 176](https://github.com/mrdoob/three.js/wiki/Migration-Guide#175--176)
- **r179:** replace deprecated `USDZLoader` with `USDLoader` for supported USD workflows. [178 → 179](https://github.com/mrdoob/three.js/wiki/Migration-Guide#178--179)
- **r180:** replace `RGBELoader` with `HDRLoader` from `three/addons/loaders/HDRLoader.js`; replace removed `RGBMLoader` with a supported HDR format/loader. [179 → 180](https://github.com/mrdoob/three.js/wiki/Migration-Guide#179--180)
- **r181 [WebGPU]:** call `await renderer.init()` before `KTX2Loader.detectSupport(renderer)`; do not use deprecated `detectSupportAsync()`. [180 → 181](https://github.com/mrdoob/three.js/wiki/Migration-Guide#180--181)
- **r184:** `FileLoader.load()` and `ImageBitmapLoader.load()` return nothing. Read results in `onLoad`, or prefer inherited `loadAsync()`. `TextureLoader.load()` remains the immediate-placeholder exception. [183 → 184](https://github.com/mrdoob/three.js/wiki/Migration-Guide#183--184)
- **r184:** remove application-level +Z-up correction for FBX; `FBXLoader` now converts +Z-up assets to +Y-up. Keep unit conversion asset-specific. [183 → 184](https://github.com/mrdoob/three.js/wiki/Migration-Guide#183--184)
- **r185:** `PLYLoader` preserves declared `float64`/`double` attributes. Replace each renderable `Float64Array` attribute with a `Float32BufferAttribute` before rendering. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)
- **r185:** do not call deprecated `DRACOLoader.setDecoderConfig()`. Configure decoder URLs with `setDecoderPath()` (or the packaged defaults), pass the loader to `GLTFLoader.setDRACOLoader()`, reuse one loader, and dispose it at final teardown. [Revision 185 `DRACOLoader`](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/loaders/DRACOLoader.js), [revision 185 `GLTFLoader`](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/loaders/GLTFLoader.js)
- Keep KTX2 transcoder assets revision-matched; `three@0.185.1` can resolve its packaged Basis files without a stale external `setTranscoderPath()`. Dispose the loader to terminate workers. [Revision 185 `KTX2Loader` source](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/loaders/KTX2Loader.js)
- `LoadingManager.onProgress` counts manager items, not bytes, and `onLoad` can run after failed items settle. Track errors explicitly when startup requires all assets. [Revision 185 `LoadingManager` source](https://github.com/mrdoob/three.js/blob/r185/src/loaders/LoadingManager.js)

## Geometry and UVs

- **r125:** remove `Face3` assumptions; raycast mesh faces are plain intersection data. Replace `BufferGeometryUtils.computeTangents()` with `geometry.computeTangents()`. [r124 → r125](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r124--r125)
- **r144:** normalized `BufferAttribute` getters now normalize stored values, and setters denormalize their inputs. Update legacy setter calls to pass normalized values such as `1`, not raw byte values such as `255`. Continue to construct byte color attributes with `normalized: true`, for example `new THREE.BufferAttribute(bytes, 3, true)`. [r143 → r144](https://github.com/mrdoob/three.js/wiki/Migration-Guide#143--144)
- **r151:** after changing `InstancedMesh` transforms, recompute its bounding sphere before culling or raycasting; compute its box too when application logic uses it. [150 → 151](https://github.com/mrdoob/three.js/wiki/Migration-Guide#150--151)
- **r151:** set `texture.channel` explicitly for AO and light maps; use channel `1` when a map uses the second UV set because these maps no longer select it implicitly. [150 → 151](https://github.com/mrdoob/three.js/wiki/Migration-Guide#150--151)
- **r152:** rename UV attributes `uv, uv2, uv3, uv4` to `uv, uv1, uv2, uv3`. Select them with `texture.channel = 0, 1, 2, 3`. [151 → 152](https://github.com/mrdoob/three.js/wiki/Migration-Guide#151--152)
- **r159:** replace singular `attribute.updateRange` with `addUpdateRange(startComponent, componentCount)` and `clearUpdateRanges()`; ranges count array components. [r158 → r159](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r158--r159)
- **r163:** replace the `TextGeometry` option `height` with `depth`. [162 → 163](https://github.com/mrdoob/three.js/wiki/Migration-Guide#162--r163)
- **r176:** replace the `CapsuleGeometry` positional name `length` with `height`; 0.185.1 also accepts `heightSegments` as its fifth argument. Recheck cap topology and UV-dependent assets made before the rewrite. [175 → 176](https://github.com/mrdoob/three.js/wiki/Migration-Guide#175--176), [revision 185 source](https://github.com/mrdoob/three.js/blob/r185/src/geometries/CapsuleGeometry.js)
- **r185 packaging:** host/copy typeface JSON yourself; published `three@0.185.1` excludes `examples/fonts`. [r185 change](https://github.com/mrdoob/three.js/pull/33744)

## Controls and interaction

- **r120:** migrate custom mouse/touch hooks around Orbit, Trackball, and Transform controls to Pointer Events. For GLSL 3 shaders from the same baseline, set `glslVersion` rather than writing `#version`. [r119 → r120](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r119--r120)
- **r123:** `DragControls` uses Pointer Events. [r122 → r123](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r122--r123)
- **r133:** `Raycaster.intersectObject(s)` now defaults `recursive` to `true`; pass `false` only for intentional root-only tests. [132 → 133](https://github.com/mrdoob/three.js/wiki/Migration-Guide#132--133)
- **r168:** replace `DragControls.activate()/deactivate()` with `connect()/disconnect()`, access `objects` and `raycaster` properties directly, and replace `PointerLockControls.getObject()` with `.object`. [167 → r168](https://github.com/mrdoob/three.js/wiki/Migration-Guide#167--r168)
- **r169:** do not add `TransformControls` itself to the scene; add `controls.getHelper()`, and remove that helper during teardown. [168 → 169](https://github.com/mrdoob/three.js/wiki/Migration-Guide#168--169)
- **r175:** pass a DOM element to `controls.connect(element)` when reconnecting controls. `enabled = false` is not listener teardown; use `disconnect()` or `dispose()`. [174 → 175](https://github.com/mrdoob/three.js/wiki/Migration-Guide#174--175), [0.185.1 controls contract](https://threejs.org/docs/pages/Controls.html)
- **r184:** retest `FirstPersonControls`; pointer capture, press-drag look, mouse buttons, and touch behavior changed. Do not call its deprecated `handleResize()` stub. [183 → 184](https://github.com/mrdoob/three.js/wiki/Migration-Guide#183--184), [revision 185 source](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/controls/FirstPersonControls.js)
- **0.185.1 API status:** the 184 → 185 guide has no interaction-specific public API migration. Do not invent one. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)

## Materials and color

- **r119:** replace `MeshPhysicalMaterial.transparency` with `transmission`. [r118 → r119](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r118--r119)
- **r152:** replace `outputEncoding`, `Texture.encoding`, `sRGBEncoding`, and `LinearEncoding` with `outputColorSpace`, `Texture.colorSpace`, `SRGBColorSpace`, and `LinearSRGBColorSpace`. Color management and sRGB screen output are defaults. [151 → 152](https://github.com/mrdoob/three.js/wiki/Migration-Guide#151--152)
- Mark PNG/JPEG color maps as `SRGBColorSpace`; leave normal, roughness, metalness, AO, alpha, and other data maps at `NoColorSpace`. HDR/EXR color data is Linear-sRGB. [Official color-management guide](https://threejs.org/manual/en/color-management.html)
- **r158:** retune `bumpScale` if old content compensated for UV scale; its meaning became UV-scale invariant. [157 → 158](https://github.com/mrdoob/three.js/wiki/Migration-Guide#157--158)
- **r163:** use `scene.environmentIntensity` for inherited scene lighting; `material.envMapIntensity` affects only an explicit material `envMap`. [162 → 163](https://github.com/mrdoob/three.js/wiki/Migration-Guide#162--r163)
- **r170:** do not mutate `Material.type`; it is static/read-only metadata. Use material feature state, `needsUpdate`, and `customProgramCacheKey()` for shader variants. [169 → 170](https://github.com/mrdoob/three.js/wiki/Migration-Guide#169--170)
- **r178:** set `material.premultipliedAlpha = true` when retaining `MultiplyBlending` or `SubtractiveBlending`. [177 → 178](https://github.com/mrdoob/three.js/wiki/Migration-Guide#177--178)
- **r181:** re-baseline PBR visuals: indirect specular, rough-material energy conservation, and PMREM filtering changed. Do not counteract all three with a compatibility shader. [180 → 181](https://github.com/mrdoob/three.js/wiki/Migration-Guide#180--181)
- **r184:** remove old sign/axis compensations from `backgroundRotation`, `environmentRotation`, and material environment rotation; convention now matches object rotation. [183 → 184](https://github.com/mrdoob/three.js/wiki/Migration-Guide#183--184)

## Shaders and TSL

- **r120 [WebGL]:** for GLSL ES 3, set `glslVersion: THREE.GLSL3`; never place `#version` in custom source. Use matching `in`/`out` declarations and a declared fragment output. [r119 → r120](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r119--r120)
- **r154 [WebGL]:** replace shader chunks `encodings_fragment` → `colorspace_fragment` and `output_fragment` → `opaque_fragment`. The latter is not the final output transform. [153 → 154](https://github.com/mrdoob/three.js/wiki/Migration-Guide#153--154)
- **r155 [WebGL]:** a `ShaderMaterial` rendered to screen must finish with tone mapping, when intended, then `colorspace_fragment`. Do not apply this conversion to intermediate targets that later use `OutputPass`. [154 → 155](https://github.com/mrdoob/three.js/wiki/Migration-Guide#154--155)
- **r157 [WebGL]:** remove custom shader references to the deleted `GeometricContext` struct. [156 → 157](https://github.com/mrdoob/three.js/wiki/Migration-Guide#156--157)
- **r163 [WebGL]:** remove WebGL 1 extension-era assumptions. WebGLRenderer is WebGL 2 only; revision 185 `ShaderMaterial.extensions` retains only `clipCullDistance` and `multiDraw`. [162 → 163](https://github.com/mrdoob/three.js/wiki/Migration-Guide#162--r163), [revision 185 source](https://github.com/mrdoob/three.js/blob/r185/src/materials/ShaderMaterial.js)
- **r164 [WebGL]:** inline or redesign code that depended on removed `lightmap_fragment`; shader chunks are revision-private implementation details. [163 → r164](https://github.com/mrdoob/three.js/wiki/Migration-Guide#163--r164)
- **r171 [WebGPU]:** import renderer and NodeMaterial APIs from `three/webgpu`; import TSL functions from `three/tsl`. Classic `ShaderMaterial` and `RawShaderMaterial` remain WebGL-only. [170 → 171](https://github.com/mrdoob/three.js/wiki/Migration-Guide#170--171)
- **r185 [TSL]:** in `material.positionNode`, `positionLocal` does not update internal vertex transformations such as `SkinnedMesh`; use `positionGeometry` to read the pre-transformed geometry attribute, and explicitly compose any required internal transforms. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185), [revision 185 NodeMaterial position setup](https://github.com/mrdoob/three.js/blob/r185/src/materials/nodes/NodeMaterial.js#L763-L807)
- **r185 [WebGL]:** replace deprecated `inverseTransformDirection()` with `transformNormalByInverseViewMatrix()` for normals or `transformDirectionByInverseViewMatrix()` for directions. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)

## Post-processing

- **r155 [WebGL]:** end a normal `EffectComposer` chain with parameterless `OutputPass`; it applies renderer tone mapping, exposure, and output color conversion. Replace `GammaCorrectionShader` as the general final-output step. [154 → 155](https://github.com/mrdoob/three.js/wiki/Migration-Guide#154--155)
- Keep linear-space effects and `SMAAPass` before `OutputPass`; place `FXAAPass` after it because FXAA expects sRGB input. Let composer `setSize()` propagate effective DPR-scaled dimensions. [Revision 185 `FXAAPass`](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/postprocessing/FXAAPass.js), [revision 185 `SMAAPass`](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/postprocessing/SMAAPass.js)
- **r156 [WebGL]:** construct `FilmPass(intensity, grayscale)` without scanline parameters; place `SSAOPass` after a `RenderPass`. [155 → 156](https://github.com/mrdoob/three.js/wiki/Migration-Guide#155--156)
- **r160 [WebGL]:** replace removed `HBAOPass` with `GTAOPass`. [r159 → r160](https://github.com/mrdoob/three.js/wiki/Migration-Guide#r159--r160)
- **r175 [WebGL]:** remove width/height constructor arguments from `SMAAPass` and `HalftonePass`; composer sizing owns them. [174 → 175](https://github.com/mrdoob/three.js/wiki/Migration-Guide#174--175)
- **r179 [WebGPU]:** replace `TRAAPassNode` with `TRAANode` and rebuild from the revision 185 setup rather than renaming only the symbol. [178 → 179](https://github.com/mrdoob/three.js/wiki/Migration-Guide#178--179)
- **r180 [WebGPU]:** migrate `DepthOfFieldNode` to its new scene-color plus view-Z API. [179 → 180](https://github.com/mrdoob/three.js/wiki/Migration-Guide#179--180)
- **r181 [WebGPU]:** replace `PassNode.setResolution()/getResolution()` with `setResolutionScale()/getResolutionScale()`. [180 → 181](https://github.com/mrdoob/three.js/wiki/Migration-Guide#180--181)
- **r183 [WebGPU]:** replace `PostProcessing` with `RenderPipeline`. Compose scene/effect texture nodes into `outputNode`; do not add the WebGL `OutputPass`. [182 → 183](https://github.com/mrdoob/three.js/wiki/Migration-Guide#182--183), [revision 185 `RenderPipeline`](https://github.com/mrdoob/three.js/blob/r185/src/renderers/common/RenderPipeline.js)
- **r185 [WebGPU]:** remove `SSAAPassNode.clearColor` and `.clearAlpha`; set clear state on the renderer. Replace removed `AnamorphicNode` with `BloomNode`. Retune `GTAONode` toward lower `radius` and `scale` if the new AO is too wide or dark. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)
- **r185 [WebGPU]:** update `SSRNode` and `SSGINode` integrations from their revision 185 examples; both node setups changed. [184 → 185](https://github.com/mrdoob/three.js/wiki/Migration-Guide#184--185)
- Dispose composers, pipelines, passes, and application-owned render targets when retired. Avoid per-frame resize, pass construction, shader recompilation, and resource allocation. [Revision 185 `EffectComposer`](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/postprocessing/EffectComposer.js)

## Final cutover audit

- Search the application for every old symbol named above; remove compatibility aliases and deprecated fallback branches after migrating all callers.
- Run visual comparisons for lighting, PBR/PMREM, environment rotation, shadows, alpha compositing, AO, DOF, and post-processing output; these revisions intentionally changed appearance.
- Verify each deployed addon and decoder URL resolves to the 0.185.1 asset set, and verify teardown by mounting/unmounting or rebuilding the scene repeatedly.
- Primary authorities: [official migration guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide), [revision 185 tag](https://github.com/mrdoob/three.js/tree/r185), and [r185 release notes](https://github.com/mrdoob/three.js/releases/tag/r185).
